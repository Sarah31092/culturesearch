AI 문화행사 추천 프로젝트

1. 아키텍처와 폴더
- FastAPI가 화면, JSON API, MCP용 HTTP 엔드포인트를 제공한다.
- 화면은 HTML 템플릿, CSS, 브라우저 JavaScript로 구성하며 React는 사용하지 않는다.
- backend/app/main.py: 웹 라우트, 데이터 상태와 API
- backend/app/data_pipeline.py: 원본 CSV를 읽고 전처리하여 SQLite에 저장
- backend/app/database.py, models.py: SQLAlchemy 설정과 행사 테이블
- backend/app/rag.py: ChromaDB용 로컬 벡터 임베딩과 유사 검색
- backend/app/mcp_tools.py: 검색 도구 함수, 도구 설명, HTTP MCP 호출
- backend/app/agent.py: 사용자 요청 해석, 행사 검색, 근거 기반 답변
- backend/app/templates/index.html: 검색·추천 화면
- backend/app/static/style.css, app.js: 화면 스타일과 API 연동
- backend/scripts/build_data.py: CSV DB 적재를 수동 실행
- backend/scripts/build_embeddings.py: 임베딩 생성을 수동 실행
- backend/mcp_server.py: MCP Python SDK 기반 stdio 도구 서버
- backend/data: 제공된 CSV 파일 3개만 사용
- backend/culture.db 및 backend/chroma: 실행 과정에서 생성되는 저장소

2. 데이터 처리
- CSV의 실제 헤더를 기준으로 서울시 행사, 전국 축제, 전국 공연 컬럼을 매핑한다.
- 원본은 읽기만 하며 cp949 인코딩을 사용한다.
- 제목이 없는 행은 건너뛰고 제목·지역·구·장소·기간이 같은 중복 행을 제거한다.
- 기간을 YYYY-MM-DD 형식으로 정리하고 지역명 및 좌표를 표준 필드에 저장한다.
- 전국 축제 데이터는 축제, 전국 공연 데이터는 공연으로 분류한다.
- 서울 자료는 CSV의 테마분류, 행사명과 설명의 키워드가 확인될 때만 다섯 유형 중 하나로 분류한다.
- 확인할 수 없는 유형은 미분류이며, 데이터가 없는 유형은 API 및 화면에서 미지원으로 표시한다.
- 데이터 적재 시 기존 events 레코드를 교체하며 원본 파일은 수정하지 않는다.

3. 저장 및 검색
- SQLite에 행사명, 유형, 지역, 장소, 날짜, 설명, 연락처, 좌표 등 제공된 정보를 저장한다.
- 통합 검색은 키워드, 지역, 구, 날짜, 유형 조건을 함께 적용할 수 있다.
- 축제·전시·공연·체험 유형 검색은 한국 날짜 기준 오늘 종료일이거나 이후 종료하는 행사만 표시한다. 종료일이 없는 데이터는 시작일이 오늘 이후인 경우 포함하며, 특정 날짜를 요청하면 그 날짜 진행 행사로 검색한다.
- 상세정보 조회는 행사 ID를 이용한다.
- 목록이 비어 있으면 빈 목록과 사용자 안내를 반환한다.

4. RAG 구성
- backend/scripts/build_embeddings.py를 개발자가 직접 실행해 ChromaDB에 저장한다.
- 문서는 행사명, 유형, 지역, 장소, 분류, 설명, 주소 등 DB의 값으로만 구성한다.
- 임베딩은 외부 API를 호출하지 않는 로컬 해시 기반 벡터이며, ChromaDB cosine 유사도 검색을 이용한다.
- 사용자 질의에 대해 관련 행사 문서를 검색하고 실제 행사 레코드만 답변 근거로 전달한다.
- 임베딩이 준비되지 않은 경우 유사 검색은 빈 목록으로 응답한다.

5. MCP 구성
- MCP Python SDK의 stdio 서버를 backend/mcp_server.py에서 실행한다.
- 제공 도구: culture_search, region_search, date_search, type_search, event_detail, similar_search.
- /api/mcp/tools에서 도구 설명과 입력 스키마를 확인하고 /api/mcp/call에서 호출할 수 있다.
- 날짜는 YYYY-MM-DD, 행사 유형은 축제·공연·전시·체험·문화강좌를 기준으로 한다.

6. AI 에이전트와 질의응답
- 요청 문장에서 전국 시도, 다섯 행사 유형, 유효한 날짜를 추출해 DB 검색 조건으로 사용한다.
- 명시한 지역·유형·날짜 조건에 맞는 데이터가 없을 때 조건과 다른 행사를 임의 추천하지 않는다.
- 필터가 없는 자연어 요청은 키워드 검색 및 RAG 유사 검색을 시도한다.
- OPENAI_API_KEY가 설정되면 검색 결과만 근거로 OpenAI 답변을 생성한다.
- 키가 없거나 호출이 실패해도 실제 DB 검색 결과만으로 안내하며, 확인되지 않은 행사 세부정보를 만들지 않는다.

7. 화면 및 기능 테스트
- 메인 화면: 데이터 건수, 유형별 지원 여부, 빠른 검색, 최신 결과
- 통합·지역·날짜·유형별 검색과 행사 상세정보 모달
- AI 맞춤 추천 및 RAG 질의응답 결과·검색 근거 표시
- README.md에 설치, 데이터 적재, 임베딩 생성, 웹 실행, API 테스트, MCP 연결 절차를 기록한다.
- 권장 테스트 순서: CSV 적재 → /api/status → 검색 필터 및 상세조회 → 임베딩 생성 → 유사 검색/질의응답 → MCP 도구 목록과 호출
